# SKALA 작전 — 앉기 · 점프 · 개인전(FFA) 계약서 (2차 확장)

이 문서는 2차 확장 작업의 공통 계약이다. 담당 파일 밖은 고치지 않는다(ARCHITECTURE.md 3절).
다른 사람이 같은 파일을 고치고 있을 수 있으니 **편집 직전에 다시 읽고, 작은 단위로 고친다.**
커밋·푸시는 메인테이너만 한다.

이미 반영된 것(메인테이너):
- `maps/builder.js`: solids의 `mat: 'clip'` = 보이지 않는 막이(충돌만, 총알·시야 통과, 그리지 않음)
- `game/protocol.js`: 상태 플래그 `FLAG.crouch = 32` (`encodeState`의 `s.crouch` ↔ `decodeState().crouch`)
- `engine/renderer.js`: 자동 품질의 그림자 전환은 미뤄 두고 `renderer.applyPendingQuality()`로 안전한 때 적용
  (`world.setRound({phase}≠live)`·`world.killLocal()`·`map:loading`에서 부름)

## 1. 점프 (core)
- `PLAYER.JUMP_V` 5.2 → **6.3** (최고 높이 ≈ 1.24 m. 공중 턱 오르기 0.225 m를 더하면 약 1.46 m 높이까지 올라탈 수 있다).
  지금은 0.85 m(+0.225)라 1.2~1.4 m 지형지물(파이프 랙, 방유제 벽, 상자)을 못 넘는다는 피드백.
- 중력(-16)은 그대로. 낙하 피해 없음은 그대로.
- **맵 경계**: 물가 난간·선박 난간을 점프로 넘어 물/맵 밖으로 떨어지면 안 된다. 각 맵 담당이 그런 곳에
  `{ type:'box', ..., mat:'clip' }` 막이(난간 위로 3 m 정도)를 넣는다. 점프로 올라가게 된 새 위치가 맵을 깨면(지붕 위 등) 그곳도 막는다.
- 봇 길찾기: `navgrid` `jumpHeight` 0.8 → 약 **1.2**(물리 한계 1.46보다 여유 있게).

## 2. 앉기 (core 중심)
| 항목 | 값 |
|---|---|
| 키 | **Ctrl(왼·오른쪽) 또는 C**, 누르고 있는 동안 앉기 |
| 키 높이 / 눈높이 | 1.8 → **1.25** / 1.6 → **1.1** (0.12초 부드럽게 전환) |
| 이동 속도 | **2.6 m/s** (Shift 천천히 걷기 2.4와 비슷), 발소리 작게 |
| 일어서기 | 머리 위가 막혀 있으면 일어서지 않고 앉은 채 유지 |
| 점프 | 앉은 채 Space → 일어설 수 있으면 일어서며 점프, 막혀 있으면 점프 안 함 |
| 탄퍼짐 | 앉아 있으면 ×0.8 (가능하면) |
| 상태 | `player.state.crouch`(bool), `player.snapshot().crouch`, 원격은 상태 플래그 `crouch` |
| 히트박스 | `consts.HITBOX_CROUCH` = HEAD `{y:1.12, r:0.14}`, BODY `{y0:0.6, y1:1.05}`, LEGS `{y0:0, y1:0.6}` (hw·hd는 서 있을 때와 같음) |
| 레이 판정 | 액터 히트박스 레이 함수에 `crouch` 옵션 → `HITBOX_CROUCH` |
| 아바타 | `avatars` 상태에 `crouch` → 앉은 자세(무릎 굽힘, 몸 낮춤) |

- **Ctrl+W 주의**: 브라우저는 Ctrl+W(탭 닫기)를 페이지가 막지 못한다. 그래서
  ① C 키도 같이 지원, ② 연습장·경기 화면(`sandbox`·`match`)에 있는 동안 `beforeunload` 확인으로 실수로 탭이 닫히지 않게,
  ③ 조작법에 "앉은 채 앞으로 갈 때는 C 추천(Ctrl+W는 브라우저 탭 닫기)" 안내.
  ④ (선택) 전체 화면일 때 `navigator.keyboard.lock()`이 되면 Ctrl 조합도 게임이 받는다.

## 3. 개인전 FFA (match · bots · ui · practice/world · session)
### 3.1 규칙 (`match.js`, `rules.mode`)
| rules | 기본 | 의미 |
|---|---|---|
| `mode` | `'team'` | `'team'`(지금 그대로) / `'ffa'`(개인전) |
| `killTarget` | 20 | 먼저 이 킬 수에 닿으면 우승. match.js는 5~50으로 자르고(연습장 주소 값), 멀티 방은 **방장이 5~20 안에서 고른다**(`modes.FFA_KILLS`). 승리 보상은 목표 킬에 비례한다(20킬 판이 전부, DESIGN 7절) |
| `timeLimitMs` | 300000 | 5분. 끝나면 킬 많은 순(동률이면 데스 적은 순 → 헤드샷 많은 순 → 그래도 같으면 무승부) |
| `respawnMs` | 3000 | 죽고 나서 부활까지 |
| `spawnProtectMs` | 1500 | 부활 직후 무적. 그 사람이 먼저 공격(히트 주장)하면 바로 끝 |
| `loadoutMs` | 5000 | 처음 출격 전 무기 선택 |

- 페이즈: `warmup → loadout → live → matchEnd` (라운드 없음, `round = 1`, `roundEnd` 없음).
- `start()`: 2명 이상(봇 포함). 팀 검사 없음. FFA에서 플레이어 `team = null`, `setTeam`은 reject.
- `setLoadout(id, primary)`: FFA에서는 loadout·live 모두 허용, **다음 부활부터** 적용(죽어 있으면 이번 부활에 바로).
- 죽으면 `respawnAt`(방장 시계) 기록 → 시간이 되면 이벤트 `{ type:'spawn', id, spawn:{x,y,z,rotY}, loadout, protectMs }`.
  live 시작 때 모든 플레이어도 같은 `spawn` 이벤트로 나온다(팀전의 스폰 전달 방식은 그대로 둔다).
- 스폰 위치: 맵 `spawns.owner` + `spawns.charterer`(+ 있으면 `spawns.ffa`)를 모두 후보로, **살아 있는 다른 사람과의 최소 거리가 큰 순 상위 3곳 중 무작위.**
  위치는 `createMatch({ getPositions: () => ({ [id]: { x, z } }) })` 콜백으로 받는다(없으면 최근에 쓴 2곳을 피한 무작위).
- 늦게 들어온 사람(`addPlayer` in live): 죽은 상태로 넣고 `respawnMs` 뒤 스폰.
- `removePlayer`로 접속자가 1명만 남으면 `matchEnd { winner: 남은 id, reason:'forfeit' }`.
- 킬: 공격자 `kills+1`. 자폭(자기 수류탄)은 `deaths+1`만. 헤드샷 집계는 그대로.
- `matchEnd` 이벤트(FFA): `{ type:'matchEnd', mode:'ffa', winner: id|null, reason:'kills'|'time'|'forfeit'|'draw', ranking:[{rank,id,name,kills,deaths,headshots,bot}] }`
- 스냅샷: `mode`, `killTarget`, 남은 시간(`endsAt`), 플레이어별 `kills/deaths/headshots/alive/hp/respawnIn(ms)/protect`. protocol 예산 안에서 무손실 통과(match 담당이 protocol.js의 경기 인코딩까지 맞춘다).
- `standings(view)`: FFA면 킬↓·데스↑·헤드샷↓ 순 + `ranking[{rank,...}]`, `winnerId`.
- 방장 이전 복원(`restoreMatch` 등): FFA면 킬·데스·남은 시간 유지, 모두 부활 대기에서 다시 시작.

### 3.2 봇 (`bots.js`, `navgrid.js`)
- FFA: 자기 말고 모두 적(사람·봇). 아군 오사 회피 없음. 부활 API(`spawn` 이벤트를 받은 연습장이 부르는 함수)는 BOTS_API.md에 적는다.
- 상대가 `crouch`면 조준 높이를 `HITBOX_CROUCH.HEAD.y`로.
- `jumpHeight` 약 1.2로 올리고 봇이 새 점프 간선을 제대로 쓰는지 확인.

### 3.4 연습장 · World (`practice.js`, `world.js`)
- 연습장 설정에 **모드(팀전/개인전)**. 개인전: 봇 1~7(총 8명 이하), 난이도 그대로.
- World: FFA면 다른 모든 액터가 적(히트 판정·피드백). 다른 사람 아바타는 한 가지 '적' 색. 부활: `spawn` 이벤트 → `spawnLocal`/액터 순간이동. 보호 중 표시.
- 앉기 연결: `getLocalState().crouch`, `setActorState(id, { crouch })` → 아바타 자세 + 앉은 히트박스로 레이 판정.

### 3.5 멀티 (`session.js`)
- 방 메타 `mode`(기본 'team'). 방장 `room:mode` → `updateMeta({ mode })`, 로비 목록에도 `mode`.
- 방 메타 `killTarget`(개인전 목표 킬, 없으면 20). 방장 `room:killTarget` → `updateMeta({ killTarget })`(5~20으로 자름), 로비 목록에는 `mode` 값 넷째 칸으로(`'ffa:classic::10'`). 경기는 `createMatch({ rules:{ mode:'ffa', killTarget } })`.
- FFA 방: 팀 배정 없음, 시작 2명 이상 + 준비. 경기: `createMatch({ rules:{ mode:'ffa' }, getPositions })`, `spawn` 이벤트 반영, 부활 화면(`hud.respawn` + `loadout compact`), 늦게 온 사람은 바로 참가(부활 대기 후 스폰), 방장 이전 복원, 결과 FFA.

## 4. 이모트(감정 표현) — 3차 확장
사용자 요청: "L을 가져가, 새싹 댄스, 사이드 스텝, X 점프, 탱고 같은 이모트. 누르고 있으면 휠이 뜨는 방식으로 키를 누르면 목록이 쫙 펼쳐지고,
마우스를 그쪽으로 가져가 키를 떼면 그 이모트. 움직이면 취소. 마우스를 안 움직이고 떼면 아무것도 안 함." + 소리.
- **동작은 모두 직접 만든다**(절차적 키프레임). 상용 게임의 애니메이션을 가져오거나 흉내 내어 복제하지 않는다.
- 소리는 WebAudio 합성음이 기본이다. 6종(L을 가져가·야채·크리스 크로스·크림치즈 허니·당신에게서·셀카)은 사용 권리를 확인한 음원 묶음(`audio/emotes`, docs/EMOTE_BGM.md)을 쓰고,
  춤 한 주기를 그 음원의 한 소절에 맞췄다. 묶음을 못 읽으면 합성음으로 돌아간다.
- 휠은 8칸이고 이모트는 11종이다. 휠에 무엇을 둘지는 상점의 이모트 탭에서 고른다(4.6).

### 4.2 입력 · 휠
- **B 키를 누르고 있는 동안** 화면 가운데에 8칸 원형 휠이 뜬다(12시부터 시계 방향으로 1~8번).
  - 휠이 열린 동안 **시점 회전은 멈추고** 마우스 이동은 휠의 가상 커서로 간다(포인터 잠금 유지).
  - 잠금이 없으면 실제 커서 위치를 화면 중앙 기준으로 쓴다.
- 가상 커서가 중앙에서 **40px 이상** 벗어나면 그 방향 칸이 강조된다. 반지름 밖은 테두리에 붙인다.
- **B를 떼면**:
  - 강조된 칸이 있으면 그 이모트를 시작한다.
  - **마우스를 안 움직여서 강조된 칸이 없으면 아무것도 안 한다.**
  - 떼는 순간 움직이고 있으면(이동키를 누르고 있거나 수평 속도가 0.5 m/s보다 크면) 시작하지 않고 "멈춘 상태에서만 할 수 있어요"를 띄운다.
- 휠이 열린 동안 좌클릭은 강조된 칸을 바로 시작한다(선택 사항). Esc나 우클릭은 아무것도 하지 않고 닫는다. 휠이 열린 동안 사격은 하지 않는다.
- **휴대폰**(engine/touch.js): 이모트 버튼을 누른 채 끌어 칸을 고르고 떼면 PC의 B와 같다.
  - 끌지 않고 **짧게 눌렀다 떼면 휠이 열린 채로 남는다**(탭 모드, `input:emoteWheel`의 `tap: true`). 칸을 누르면 그 이모트를 시작하고 휠을 닫는다.
  - 가운데 허브를 누르거나 이모트 버튼을 다시 누르면 고르지 않고 닫는다. 휠 밖을 누르면 닫고, 그 손가락은 원래 조작(이동·시점·버튼)이 된다. 8초 동안 아무것도 안 누르면 닫는다.
  - 칸 판정은 `wheelTapAt`(engine/touch-logic.js)이 휠 상자 크기로 계산한다. 무기 칸과 겹친 자리를 눌러도 이모트만 고른다.
- 이모트를 할 수 있는 때: 살아 있고, 땅 위에 있고, 멈춰 있을 때. 페이즈는 상관없다(로드아웃·라운드 끝·라이브 모두 가능).

### 4.3 이모트 중
- **3인칭 카메라**로 바꾼다.
  - 캐릭터 앞쪽 비스듬히 약 3 m 떨어져 캐릭터를 바라본다.
  - 마우스로 캐릭터 주위를 돈다(몸 방향은 그대로).
  - 벽에 묻히지 않게 레이로 당긴다.
- 무기 뷰모델·크로스헤어를 숨기고, 사격은 할 수 없다.
- **취소 조건**(곧바로 1인칭, 0.15초 전환):
  - WASD 이동, 점프, 앉기, 좌·우클릭, 재장전, 무기 교체(1~4·휠), B 다시 누름
  - 피해를 받았을 때, 죽거나 다시 스폰될 때
- 한 번만 하는 이모트(경례·손 흔들기)는 끝나면 1인칭으로 저절로 돌아온다.

### 4.4 전송 · 원격 (protocol은 반영 완료)
- 상태 플래그 6~9번 비트 = 이모트 번호(0~15). `encodeState`의 `s.emote` ↔ `decodeState().emote`.
- 내 상태는 `player.snapshot().emote`(또는 `getLocalState().emote`)로 보낸다.
- 원격 아바타는 번호를 받으면 그 동작을 처음부터 재생한다(반복형은 계속 반복). 0이 되면 0.15초 만에 원래 자세로 돌아온다. 원격 소리는 3D로 작게 재생한다.
- 히트박스는 이모트 중에도 서 있는 상태 그대로다.
- 연습장 봇(선택): 팀전에서 라운드를 이기거나 개인전에서 킬을 하면 30% 확률로 2~3초 동안 무작위 이모트를 한다. 움직이면 취소한다.

### 4.6 휠 커스텀 · 상점
- 휠 8칸의 이모트는 계정 장비 `loadout.emotes`(12시부터 시계 방향)에 저장한다. 처음 휠은 `DEFAULT_EMOTE_WHEEL`(L을 가져가·야채·크림치즈 허니·크리스 크로스·탱고·경례·손 흔들기·환호 박수)이다.
- 상점의 **이모트** 탭: 위쪽에서 칸을 고르고, 이모트 카드에서 `N번 칸에 넣기`(다른 칸에 있으면 `바꾸기`)를 누른다. `▶ 듣기`로 소리를 미리 들을 수 있다.
- 기본 지급 9종은 처음부터 가진다. 당신에게서(600 P)·셀카(400 P)는 사야 휠에 넣을 수 있다. 서버 가격표(`fps_item_price`)에도 같은 값이 있다.
- 가진 이모트만, 겹치지 않게 8칸을 채운다(`normalizeEmoteWheel`). 깨진 값이면 기본 휠로 돌아간다.
- 원격 플레이어에게는 이모트 번호만 간다. 상대가 내 휠 구성을 알 필요는 없다.

### 4.5 아바타 리그
- 평소에는 지금 아바타(메시 4개)를 그대로 쓴다.
- **이모트 중일 때만** 관절이 있는 리그로 바꿔 그린다.
  - 관절: 몸통·머리·위팔·아래팔·손·허벅지·정강이
  - 그래서 평소 draw call은 늘지 않는다.
- 내 캐릭터도 3인칭 이모트 중에는 같은 리그로 그린다(평소 1인칭에서는 몸이 안 보인다).
- 팀 색과 FFA 적 색은 지금 규칙 그대로 쓴다.

## 5. 폭파 미션 — 4차 확장
사용자 요청: "팀으로 하되 킬만이 아니라 주어진 미션을 성공한 팀이 이기는 모드. 공격/수비 진영으로 나누고, 미션은 상대 팀의 컴퓨터에 접근해 폭탄을 설치하는 것. 설치 구역은 A구역·B구역. 레드/블루 팀."
- 장르 관습(두 설치 구역, 설치·해체, 공수 교대)은 쓰되 맵·이름·배치는 직접 설계한다(DESIGN.md 1절, MAP_GUIDE.md 9절). 소리는 모두 WebAudio 합성이다.
- 판정은 지금 구조대로 방장 권위다. 클라이언트는 설치·해체 시작·취소 의도만 보내고, 방장의 `match.js`가 위치·생존·시간을 직접 재서 확정한다.

### 5.1 규칙 (`rules.mode: 'bomb'` — `match.js`, `mission.js`)
| 항목 | 값 |
|---|---|
| 모드 | `'bomb'`, 이름 '폭파 미션'. 팀 모드다(블루 `owner` vs 레드 `charterer`) |
| 무기 규칙 | 클래식 고정(`ruleset`을 줘도 클래식) |
| 길이 | 5판 3선승(`roundsToWin 3`, `maxRounds 5`). 무승부 라운드는 없다 |
| 라운드 | 로드아웃 5초 → live **1:40** → 결과 5초. 라운드 중 부활 없음 |
| 진영 | 1·2라운드는 `firstAttack`(기본 블루)이 공격, **2라운드가 끝나면 공수 교대**. 5라운드도 후반 진영 그대로(`mission.sideFor`) |
| 스폰 | 팀이 아니라 진영 기준: 맵 `mission.attack` / `mission.defense` |
| 폭탄 | 라운드 시작 때 공격 팀 참가자 한 명(무작위)이 든다 |
| 설치 | 폭탄을 든 사람이 A·B 구역 상자 안에서 **멈춘 채 E 3초** |
| 해체 | 수비 팀원이 설치된 폭탄 **1.5 m**(수평, 높이 차 1.6 m) 안에서 **멈춘 채 E 5초**. 한 번에 한 명 |
| 취소 | 0.6 m 넘게 움직이거나(설치는 구역 밖으로 나가도), 쏘거나(칼 포함, 수류탄은 던지는 순간 — 터질 때가 아니다), 손을 떼거나, 쓰러지면 |
| 폭발 | 설치 **35초** 뒤. 7 m 안은 즉사(500), 16 m까지 160 → 0으로 줄어든다. 벽은 보지 않는다. 폭발 킬은 아무에게도 주지 않는다(데스만 센다) |
| 떨굼·줍기 | 든 사람이 쓰러지거나 나가면 그 자리 바닥에 떨어진다(공중이면 그 아래 바닥, 연결이 끊겼으면 마지막으로 본 자리). 공격 팀원이 1.2 m 안에 서면 줍는다. 수비는 못 줍는다. 로드아웃 중에 나가면 다른 공격 팀원에게 간다 |
| 보상 | 기존 경기 보상(킬·헤드샷·승리·완주) 그대로. 설치·해체 보너스는 없다(서버 상한 그대로) |

정한 값은 `mission.js`의 `BOMB`와 `match.js`의 `DEFAULT_BOMB_RULES`에 있다. 세션은 `createSession({ bombRules })`로 시험용 값을 덮어쓴다.

### 5.2 승패
| 이긴 쪽 | 사유(`roundEnd.reason`) |
|---|---|
| 공격 | 폭탄 폭파(`bomb`) · 수비 전멸(`elimination`, 설치 전·후 모두) |
| 수비 | 폭탄 해체(`defuse`) · 설치 전 공격 전멸(`elimination`, 동시 전멸 포함) · 설치 없이 시간 종료(`time`, 설치 중이어도) |

- 설치된 뒤 공격이 전멸해도 폭발·해체까지 라운드는 이어진다.
- 설치되면 라운드 시계(1:40)는 끝을 정하지 않고 폭탄 시계(35초)가 정한다. 스냅샷 `tl`·HUD 타이머도 폭발까지 남은 시간이 된다.
- 같은 순간이면 폭발이 해체 완료보다 먼저이고(해체는 폭발 전에 끝나야 한다), 설치 완료가 시간 종료보다 먼저다.

### 5.3 방장 권위 · 전송
- 의도: `g2b [id, act, reason?]`(act 0 취소 · 1 설치 · 2 해체, reason 0 손 뗌 · 1 움직임 · 2 사격) → 방장 `match.bombIntent(id, act, { reason })`.
  방장 자신의 의도도 `sync.sendBomb`가 같은 길로 돌려준다. 두 번 보내고 받는 쪽이 id로 거른다.
- 방장은 `createMatch({ getPositions })`로 받은 발 위치(x·y·z)로 구역 안·해체 거리·움직임·줍기·폭발 피해를 잰다. 네트워크 지연 몫으로 구역은 0.5 m, 해체 거리는 0.5 m 여유를 둔다.
- 방장은 그 사람이 쏜 사격 메시지를 받거나 그 사람의 피격 주장을 처리하면 진행 중인 설치·해체를 취소한다.
- 상태: 스냅샷에 `mo:'bomb'`, `at`(이번 라운드 공격 팀), `fa`(전반 공격 팀), `bru`(설치·해체·폭발 시간, 교대 라운드), `bo`(폭탄)가 붙는다(MATCH_API.md 13절).
  이벤트는 `{ type:'bomb', act, id, site, pos, ... }` 하나로 싣는다.
- 정보: 폭탄을 누가 들었는지와 떨어진 폭탄 위치는 **화면에서** 공격 팀에게만 보인다. 전송은 모두에게 가므로 고친 클라이언트는 볼 수 있다(방장 권위 구조의 한계).
- 진행 중인 방은 팀전처럼 로비에서 잠긴다. 늦게 들어온 사람은 다음 라운드부터 참가한다.
- 방장 이전: `restoreMatch({ snapshot, players, spawns, mission, getPositions })`가 점수·라운드 기록(공격 팀 포함)을 잇고 그 라운드를 처음부터 다시 한다. 진영은 전체 라운드 번호로 센다(`roundOffset`).

### 5.5 조작
| PC | 휴대폰 |
|---|---|
| **E**를 누르고 있기(설치·해체). 떼면 취소 | 구역 안·폭탄 근처에서만 나타나는 '설치'/'해체' 버튼을 누르고 있기 |

- bus 이벤트: `input:use { down }`(engine/input.js, 터치는 `input.touch.use(down)`), 버튼 표시는 World가 `touch:use { on, label }`로 알린다.

### 5.6 봇 (`bots.js` `view.objective`, `practice.js`)
- 두뇌는 `view.objective = { pos, radius, hold, urgent, look? }`를 받으면 교전이 없을 때 그곳으로 가고, 닿으면 멈춰 둘레를 본다. `urgent`면 총소리 조사·추적보다 목표가 먼저다(BOTS_API.md 12절).
- 연습장이 목표를 정한다: 공격 = 폭탄을 든 봇은 고른 구역(급함), 떨어진 폭탄은 가장 가까운 공격 봇이 주우러, 나머지는 같은 구역으로 함께(셋째마다 한 명은 사냥), 설치 뒤에는 폭탄 둘레를 지킨다.
  수비 = 두 구역에 나눠 공격 진영 쪽을 보며 지키다가 설치되면 폭탄으로(급함).
- 설치·해체는 연습장이 판단마다(10 Hz) 본다: 폭탄을 든 봇이 구역 안에서 멈추면 설치, 수비 봇이 폭탄 1.5 m 안에서 멈추면 해체. 그동안은 서 있고, 적이 보이면 취소하고 싸운다.

### 5.7 맵 · 방
- 미션 칸이 있는 맵만 고를 수 있다(`MAP_LIST[].mission`, `maps.mapsForMode('bomb')`). 첫 미션 맵은 `relay`(중계 기지). 형식은 MAP_GUIDE.md 10절.
- 미션 맵에서도 팀전·개인전을 할 수 있다(맵 `spawns`).
- 로비 배지·방 만들기·방 화면 모드 선택에 '폭파 미션'. 고르면 규칙이 클래식으로, 맵이 미션 맵으로 바뀐다. 다른 모드로 돌아가면 전에 고른 규칙으로 돌아간다(방 화면은 맵도: 지금 맵을 그 규칙에서 못 쓰면 전 맵). 연습장 설정 시트에도 같은 모드가 있고, 폭파 미션으로 출격해도 저장하는 규칙은 전에 고른 규칙이다.
- 시험용 URL: `?sandbox=relay&mode=bomb&bots=2&bombcarrier=me|bot&bombsite=A|B`.

### 5.8 팀 이름: 오렌지 → 레드
- 두 팀의 화면 이름은 모든 모드에서 블루(`owner`)·**레드**(`charterer`, 🟥)다. 내부 id는 그대로다.
- 색은 `core/consts.js` TEAMS(아바타 옷), `ui/dom.js` TEAMS, `css/fps.css`의 `--sk-charterer`가 정한다.
