# 맵 제작 가이드

맵은 `js/maps/<id>.js`의 순수 데이터다. 형식의 기준은 `docs/ARCHITECTURE.md` 4절과 `docs/DESIGN.md` 5절이고, 이 문서는 그 형식을 빠르게 쓰는 법을 정리한다. 맵을 고칠 때마다 `npm run check:maps`를 돌린다.

## 1. 좌표 규칙

- 1 단위 = 1 m, y가 위, 지면 y = 0, 맵 중심이 원점. `size`가 플레이 영역이고 바깥은 보이지 않는 벽이다.
- `box`·`ramp`·`cyl`의 x, z는 **바닥 중심**, y는 **바닥 높이**다. 회전은 없다.
- `ramp`는 `dir`(`+x`, `-x`, `+z`, `-z`) 쪽으로 올라간다. `w`는 x 길이, `d`는 z 길이다.
- 바닥보다 낮은 상자(윗면 ≤ 0.05, y < 0)는 그 자리의 지면을 도려낸다. 물웅덩이와 구덩이를 이렇게 만든다.
- `mat: 'clip'`은 보이지 않는 막이다. 사람만 막고 총알과 시야는 통과한다. 물가와 맵 가장자리의 낮은 벽 위에 올린다.
- `theme.ground: 'none'`이면 바닥을 그리지 않고 y = 0 무한 평면만 남는다. 옥상처럼 보이는 바닥과 건물 몸통을 solid로 세울 때 쓴다(`rooftop`).

| 값 | 치수 |
|---|---|
| 몸 | 키 1.8, 앉으면 1.25, 반지름 0.35 |
| 그냥 오르는 턱 | 0.45 |
| 점프로 오르는 턱 | 1.2까지 안전, 물리 한계 약 1.46 |
| 달리기 점프 거리 | 평지 약 4 m |
| 봇이 지나가는 폭 | **1.8 이상**. 내비 칸이 1 m라서 더 좁으면 칸 중심이 안 걸릴 수 있다 |

`rotY` 규약은 두 가지다.

| 대상 | 0 | π | π/2 | -π/2 |
|---|---|---|---|---|
| 스폰, 포털 도착 (카메라가 보는 쪽) | -z | +z | -x | +x |
| sign, banner, vent, 장식 (앞면이 향하는 쪽) | +z | -z | +x | -x |

스폰 `y`를 생략하면 아래부터 첫 빈 바닥에 놓는다. 벽 속에 찍으면 벽 위로 올라가므로 벽에서 0.4 m 이상 띄운다. 지붕처럼 아래가 빈 곳에 세우려면 `y`를 적는다.

## 2. 뼈대

새 맵은 180° 대칭으로 절반만 쓰면 양 팀이 공정하다.

```js
/*
 * Date: 06NOV2026
 * Author: Minkyu Jung
 * Purpose: 이 맵이 무엇인지 한 문장으로
 */
import { box, ramp, wall, stairs, platform, doorwayWall, clipAbove, rotate180 } from './kit.js';

const solids = [
  wall(-20, -14, 20, -14, 4, 0.4, 'brick'),
  doorwayWall(-8, -14, -8, 6, 4, 0.4, 'plaster', { at: [-6, 2] }),
  stairs(12, 0, 4, 4, 3, 6, '+z', 'stone'),
  platform(12, 3, 10, 6, 6, 'wood_dark')
].flat();

const owner = [-24, -21, -18, -15].map((x) => ({ x, z: -6, rotY: -Math.PI / 2 }));

export default {
  id: 'example', name: '예시', nameEn: 'Example', desc: '한 줄 설명',
  size: { x: 56, z: 36 },
  rulesets: ['classic', 'knife'],
  theme: { sky: '#a9cde8', skyTop: '#3f78b5', fog: [40, 160], ground: 'stone' },
  spawns: {
    owner,
    charterer: rotate180(owner),
    ffa: [{ x: -10, z: 12, rotY: 0 }, /* 6곳 이상 */]
  },
  solids: [...solids, ...rotate180(solids)],
  decor: [],
  pads: [], portals: [], secrets: [], props: [], movers: []
};
```

`MAP_IDS`와 메뉴 이름은 `js/maps/index.js`에 이미 있다. `MAP_IDS` 순서가 메뉴 순서이고, 규칙마다 처음 나오는 맵이 방 만들기와 연습장의 기본 맵이다. `tag`는 메뉴 배지이고, `rulesets`를 안 적으면 `['classic','sniper']`다.

## 3. kit (`js/maps/kit.js`)

| 함수 | 돌려주는 것 | 설명 |
|---|---|---|
| `box(x, y, z, w, h, d, mat)` | 하나 | 상자 |
| `ramp(x, y, z, w, h, d, dir, mat)` | 하나 | 경사로 |
| `cyl(x, y, z, r, h, mat)` | 하나 | 세로 원통 |
| `wall(x0, z0, x1, z1, h, t, mat, y=0)` | 하나 | 축에 나란한 벽. 두 점이 중심선, `t`가 두께 |
| `pillar(x, z, h, s=0.6, mat, y=0)` | 하나 | 네모 기둥 |
| `stairs(x, y, z, w, h, d, dir, mat, steps?)` | 배열 | 속이 찬 계단. 자리 잡는 법은 `ramp`와 같다. 단 하나가 solid 하나다 |
| `platform(x, top, z, w, d, mat, { t, legs, legMat, leg, base })` | 배열 | 윗면이 `top`인 판과 네 귀 다리 |
| `doorwayWall(x0, z0, x1, z1, h, t, mat, { at, w, top, sill, y })` | 배열 | 문이 뚫린 벽. `at`은 벽 방향의 월드 좌표이고 배열이면 문이 여러 개, `w`는 폭(1.8), `top`은 윗변(2.4), `sill`을 주면 창 |
| `clipAbove(solidOrList, h=8)` | 배열 | 도형 바로 위에 보이지 않는 막이 |
| `mirrorX(list)` | 배열 | x → -x 복사본 |
| `mirrorZ(list)` | 배열 | z → -z 복사본 |
| `rotate180(list)` | 배열 | x, z 모두 뒤집은 복사본 |

- 뒤집기 함수는 복사본만 돌려준다. 원본까지 쓰려면 `[...list, ...rotate180(list)]`로 적는다.
- solids, decor, pads, portals, secrets, props, movers, 스폰을 모두 받는다. 경사로 `dir`, `rotY`, 발판 `target`·`vel`, 포털 `to`, 파이프 `from`·`to`, 움직이는 지형이 가는 방향(`dist`)을 함께 뒤집는다.
- 비밀 스팟 `id`에는 꼬리표(`_r`, `_mx`, `_mz`)가 붙어 따로 세어진다. 보상을 한 번만 줄 곳이면 복사하지 않는다.
- 배열을 돌려주는 함수를 섞었으면 `solids`에 넣기 전에 `.flat()`한다.
- 대각선 벽이나 벽 밖으로 나간 문처럼 잘못 쓰면 바로 오류가 난다.

## 4. 재질과 장식

재질은 기존 14종에 `stone, brick, plaster, tile, sand, moss, wood_dark, bamboo, paper, metal_dark, neon_cyan, neon_pink`가 더해졌다. `neon_*`은 그늘에서도 같은 밝기로 빛나고, `paper`는 창호지처럼 살짝 빛난다.

| 장식 | 필드 (y를 생략하면 0) | 기준점 |
|---|---|---|
| `tree` | `x, y, z, h=5.5, r, petals=true` | 밑동. 분홍 벚나무 |
| `bamboo` | `x, y, z, h=6, n=7, r=0.9` | 밑동. `n`줄기 무더기 |
| `lantern` | `x, y, z, r=0.28, color, cord=0.5` | 몸통 중심. 실제 조명 없음 |
| `banner` | `x, y, z, rotY, w=1.2, h=3, text, bg, fg, emblem` | 천 중심. `emblem`은 `circle, ring, diamond, blossom, blade` |
| `rope` | `from, to, sag, r, mat` | 두 끝점 |
| `vent` | `x, y, z, rotY, w, h, d, mat` | 중심. 벽에 붙이면 앞으로 튀어나온다 |
| `crateStack` | `x, y, z, rotY, size=1.1, levels=2, mat` | 바닥. 충돌 없음 |

장식은 총알이 통과하고 사람을 막지 않는다. 막아야 하면 같은 자리에 solid나 `clip`을 둔다.

## 5. 발판

```js
{ x, y, z, w, d, target: [x, y, z], apex: 3, color: '#35e0ff' }
```

- `y`는 발판을 그릴 바닥 높이다. 그 자리 바닥과 0.35 m 안이어야 발동한다.
- `target`은 착지할 **발 위치**이고 y는 그곳의 바닥 높이다. 발판 어디를 밟든 target으로 떨어진다.
- 비행 최고점은 `max(발판 y, target y) + apex`다. 머리가 그보다 1.8 m 위까지 올라가므로 그 경로에 천장이 있으면 안 된다.
- 수평 속도가 28 m/s를 넘으면 경고가 난다. `apex`를 올려 비행 시간을 늘린다.
- 도착지는 3 m 이상 넓게 만든다. 착지 뒤 약 1 m 미끄러지므로 좁은 턱에서는 떨어질 수 있다.
- `target` 대신 `vel: [vx, vy, vz]`로 속도를 직접 줄 수 있다. 이때는 밟은 자리만큼 착지점이 달라진다.

## 6. 포털과 비밀 스팟

```js
portals: [{ x, y, z, w, h, d, to: { x, y, z, rotY }, color }]
secrets: [{ id, name, x, y, z, w, h, d, points: 100, reach: 'jump' }]
```

- 둘 다 x, z는 바닥 중심, y는 바닥 높이다. 몸 중심이 사각형 안이고 몸이 상자 높이와 겹치면 발동한다.
- 포털은 얇은 쪽을 정면으로 그린다. `w`와 `d`가 비슷하면 십자로 그린다.
- 포털 `to.rotY`를 생략하면 보던 방향을 유지한다. 도착지를 다른 포털 안에 두지 않는다.
- 비밀 `id`는 맵 안에서 겹치지 않아야 한다. 계정 보상이 이 값으로 묶이므로 출시 뒤에는 바꾸지 않는다.
- 비밀 상자는 사람이 서는 자리를 덮게 놓는다. 지붕이면 `y`를 지붕 높이로, `h`를 2.5 정도로 한다.
- 검사기는 스폰에서 걷기와 점프로 닿는지, 닿을 수 있는 발판의 착지나 포털 도착이 2 m 안인지 본다. 달리기 점프로만 가는 곳은 `reach: 'jump'`를 적는다. 그러면 점프 시뮬레이션으로 실제 도달을 확인한다.

## 8. 성능 한도

`consts.LIMITS`를 넘으면 맵이 불러와지지 않는다.

| 항목 | 한도 |
|---|---|
| solids | 400 |
| decor | 280 |
| pads, portals | 각 16 |
| secrets | 8 |
| props | 40 |
| movers | 8 (문 포함) |
| 실제 조명 | 4 (앞쪽 `light`부터, 나머지는 발광 구) |

- solids는 재질별로 합쳐져 재질 하나가 드로우콜 하나다. 긴 경사가 필요하면 `stairs`보다 solid 하나인 `ramp`가 싸다.
- `sign`은 하나마다 드로우콜 하나다. `banner`는 같은 그림끼리 합쳐진다.
- 나무는 한 그루에 약 600삼각형, 대나무는 줄기 하나에 약 250삼각형이다. 합쳐서 인스턴싱되지만 삼각형 수는 그대로 늘어난다.
- 시야가 짧은 맵은 `theme.fog`를 당겨 먼 곳을 가린다.

## 9. 직접 설계 원칙

상용 게임의 맵 구조, 이름, 배치를 복제하지 않는다. 좁은 교전 구역이나 공중 가속 같은 장르 관습은 써도 되지만 레이아웃과 이름은 직접 설계한다. 외부 이미지와 음원 파일은 쓰지 않고, 표지판과 현수막의 글자도 직접 지은 것만 쓴다.

## 10. 폭파 미션 칸

폭파 미션은 공격 진영이 A·B 구역 중 한 곳에 폭탄을 설치하고, 수비 진영이 지키거나 해체하는 모드다. 맵에 `mission` 칸이 있어야 고를 수 있고 규칙은 늘 클래식이다. 예시는 `js/maps/relay.js`(중계 기지), `railyard.js`(화물 조차장), `observatory.js`(사막 관측소)다.

```js
mission: {
  sites: [
    { id: 'A', name: 'A 구역 · 서버 홀', x, y, z, w, h, d },
    { id: 'B', name: 'B 구역 · 안테나 마당', x, y, z, w, h, d }
  ],
  attack:  [{ x, z, rotY }, /* 4~5곳 */],
  defense: [{ x, z, rotY }, /* 4~5곳 */]
},
spawns: { owner: /* attack 복사본 */, charterer: /* defense 복사본 */, ffa: [/* 6~8곳 */] },
rulesets: ['classic'],
tag: '폭파 미션'
```

| 필드 | 뜻 |
|---|---|
| `sites[].x`, `z` | 구역 바닥 중심 |
| `sites[].y` | 구역 바닥 높이. 판정 높이는 `y − 0.6`부터 `y + h`까지 |
| `sites[].w`, `d` | x 길이, z 길이 |
| `sites[].h` | 구역 높이. 생략하면 3 |
| `sites[].name` | 화면에 보이는 이름. 32자까지 |
| `attack`, `defense` | 진영 스폰. `rotY`는 1절 스폰 규약이고 `y`를 적으면 그 높이 근처 바닥에 선다 |

읽기와 구역 판정은 `js/game/mission.js`의 `normalizeMission`·`siteContains`가 한다. 게임과 검사기가 같은 함수를 쓴다.

### 구역

- `id`는 `A`와 `B`다. 크기는 7×7~10×10 m가 알맞다.
- 구역 안 바닥은 한 높이로 평평하게 둔다. 경사로나 계단을 걸치지 않는다.
- 설치할 빈 바닥을 25 m² 이상 남긴다. 엄폐물 사이 통로는 1.8 m 이상이다.
- 수비 팀 컴퓨터(서버 랙, 단말 콘솔)를 구역 안에 둔다. `metal_dark` 상자에 `neon_*` 띠를 붙이고 화면은 `sign`으로 그린다.
- 다가오는 길마다 큰 `A`·`B` 글자판을 건다. 노랑 바탕에 검은 글자처럼 대비가 큰 색을 쓴다.
- 구역 둘레에 얇은 `neon_*` 띠(높이 0.02)를 깔면 설치 범위가 바닥에서 바로 보인다.

### 진영과 스폰

- 2라운드가 끝나면 공수가 바뀐다. 그래서 스폰은 팀이 아니라 진영(`attack`, `defense`) 기준이다.
- 진영마다 4~5곳을 1 m 이상 띄워 둔다. 구역 안에는 두지 않는다.
- 적 진영 스폰이 바로 보이지 않게 벽으로 가린다.
- 팀전·개인전도 같은 맵에서 한다. `spawns.owner`는 `attack`, `spawns.charterer`는 `defense`의 복사본으로 두고 `ffa`를 6~8곳 고르게 둔다.

| 걷는 거리 | 기준 |
|---|---|
| 수비 스폰 → 구역 | 20~40 m |
| 공격 스폰 → 구역 | 50~80 m |
| 차이 | 공격이 15 m 이상 길다. 10 m보다 작으면 검사기가 경고한다 |

### 검사

`npm run check:maps`는 `mission`이 있는 맵만 본다. 새 맵 규칙이라 경고도 0이어야 한다.

| 검사 | 내용 |
|---|---|
| 구역 | `A`와 `B`가 있는지, 맵 크기 안인지, 서로 겹치지 않는지 |
| 바닥 | 구역 상자 안 걷기 칸(내비 1 m 칸)이 16칸 이상인지. 칸 수와 넓이를 출력한다 |
| 스폰 | 진영마다 4곳 이상인지, 팀 스폰과 같은 설 자리 검사, 구역 밖인지, 적 진영 스폰이 보이는지 |
| 길 | 진영 스폰마다 각 구역까지 내비 경로가 있는지. 끝점은 구역 중심에 가장 가까운 걷기 칸이다 |
| 거리 | 진영별 최단·평균 길이를 출력한다. 수비 최단이 공격 최단보다 10 m 이상 짧지 않으면 경고 |

```text
[relay] (new-map rules)
  mission: 공격 스폰 5 · 수비 스폰 5
  A: 공격 56 m(평균 57) / 수비 26 m(평균 28) · 바닥 79칸 79 m² · A 구역 · 서버 홀
```

`--json`에는 맵마다 `mission: { sites: [{ id, name, nodes, area, attack: { min, avg, n }, defense }], attack, defense, los }`가 붙는다. `mission`이 없는 맵은 `null`이다. 테스트에서는 `checkMission(data, nav, out)`을 바로 부른다.

메뉴는 `js/maps/index.js`의 `MAP_LIST` 항목 `mission`과 `mapsForMode('bomb')`로 폭파 미션 맵을 거른다.

## 11. 움직이는 지형

`movers`는 정해진 길을 왕복하는 상자다. 벽처럼 사람·총알·수류탄을 막고, 위에 선 사람을 싣고 가고, 길에 선 사람을 밀고 간다.
판정은 `js/engine/movers.js`가 하고 게임과 검사기가 같은 함수를 쓴다. 예시는 `js/maps/cqb.js`(미는 엄폐물)와 `js/maps/sorthub.js`(리프트·셔터·수레)다.
같은 칸에 `door`를 적으면 주기 대신 사람을 보고 움직이는 **문**이 된다(아래 "가까이 오면 열리는 문"). 예시는 `js/maps/karaoke.js`(자동문)와 `js/maps/hanok.js`(미닫이문)다.

```js
movers: [
  { id: 'sled_n', x, y, z, w, h, d, mat: 'steel',   // 쉬는 자리의 상자(box와 같은 규약: x·z 바닥 중심, y 바닥 높이)
    axis: 'x',        // 'x' | 'y' | 'z'
    dist: 8,          // 쉬는 자리에서 axis 방향으로 가는 거리(m). 음수면 반대쪽
    period: 12,       // 한 주기(초): 쉼 → 감 → 쉼 → 돌아옴
    hold: 1.5,        // 양 끝에서 쉬는 시간(초, 기본 1). 편도 이동 시간 = period / 2 − hold
    phase: 0 }        // 주기를 앞당기는 비율 0~1(기본 0)
]
```

| 규칙 | 값 |
|---|---|
| 개수 | 맵마다 8개까지(`LIMITS.MOVERS`) |
| 편도 이동 시간 | 1.5초 이상 |
| 가장 빠른 순간 | 3 m/s 이하. `1.5 × |dist| ÷ 편도 이동 시간`(출발과 도착은 부드럽게 빨라졌다 느려진다) |
| 시계 | 멀티는 방장 시계, 연습장은 경기 시각(일시정지하면 멈춘다). 위치가 시각의 함수라 따로 보내지 않아도 모든 화면에서 같은 자리다 |
| 뒤집기 | `rotate180`·`mirrorX`·`mirrorZ`가 자리와 가는 방향을 함께 뒤집고 id에 꼬리표를 붙인다. 돌린 쌍은 같은 시각에 서로 대칭인 자리에 있다 |

쓰는 법은 세 가지다.

- **미는 엄폐물**(수평): 길 한가운데를 오가는 판이나 수레. 지나가는 띠에는 도형·소품·스폰·발판을 두지 않는다.
  멈추는 자리 앞 1.5 m와 길 옆 한쪽 1.9 m를 비운다(밀려 온 사람이 벽에 끼이지 않고, 옆으로 비켜 갈 수 있게). 바닥에 얇은 레일(높이 0.05 이하)을 깔아 길을 알려 준다.
- **리프트**(수직): 바닥에 묻힌 기둥으로 만든다. `h`를 오르는 높이 + 0.4쯤으로 하고 쉬는 자리의 윗면을 바닥에서 0.2 m 올려 둔다(`y = 0.2 − h`).
  기둥이라 아래로 사람이 들어갈 수 없다. 다 올라간 윗면은 도착할 바닥과 높이를 맞추고, 그 위 2.2 m를 비운다.
- **셔터**(수직): 문보다 얇은 판이 문 위 벽 속으로 올라간다. 위아래로 움직이는 상자는 자기보다 넓은 도형 속으로 들어가도 된다.
  닫힐 때 문턱에 선 사람은 옆으로 밀려난다.

주의할 점

- 봇의 길 찾기는 움직이는 지형을 보지 않는다(없는 것으로 친다). 그래서 움직이는 지형으로만 갈 수 있는 곳을 만들지 않는다. 리프트로 가는 층에는 계단도 둔다.
- 폭파 구역과 겹치게 두지 않는다(설치한 폭탄 위를 지나간다).
- 탄흔은 남지 않고, 물리 소품과는 부딪히지 않는다.
- 그릴 때 위아래에 노란 띠가 저절로 둘린다(재질이 `yellow`면 어두운 띠).

### 가까이 오면 열리는 문

```js
movers: [
  { id: 'door_1', x, y, z, w: 1.8, h: 2.3, d: 0.1, mat: 'paper',   // 닫힌 자리의 문짝(문간을 꼭 채운다)
    axis: 'x',        // 열릴 때 가는 방향. 'x'·'z' = 옆 벽 속으로, 'y' = 문 위 벽 속(+)이나 바닥 속(−)으로
    dist: 1.83,       // 가는 거리(m). 옆으로 여는 문은 문짝 길이보다 조금 길게(끝이 문설주 면보다 들어가 벽 속에 숨는다)
    door: true }      // 또는 { range: 1.5, open: 0.25, close: 0.5, linger: 0.6 }
]
```

| `door` 칸 | 기본 | 범위 | 뜻 |
|---|---|---|---|
| `range` | 1.8 m | 0.8~6 | 닫힌 문짝(바닥 사각형)에서 이 거리 안에 살아 있는 사람이 있으면 열린다. 다른 층에 선 사람은 세지 않는다 |
| `open` | 0.25초 | 0.1~5 | 다 열리는 데 걸리는 시간. 빨리 열리기 시작해 부드럽게 멈춘다 |
| `close` | 0.5초 | 0.1~5 | 다 닫히는 데 걸리는 시간 |
| `linger` | 0.6초 | 0~10 | 마지막 사람이 떠난 뒤 닫히기 시작할 때까지 |

- 문은 주기가 없다(`period`·`hold`·`phase`를 적지 않는다). 사람이 가까이 있는 동안에는 닫히지 않으므로 문에 끼이지 않고, 그래서 속도 한도(3 m/s)도 없다.
- 문의 자리는 화면마다 자기가 보는 사람 위치로 정한다. 보내는 메시지가 없고, 늦게 들어온 사람도 금방 같은 상태가 된다. 남이 연 문은 보간 지연(약 0.1초)만큼 늦게 열려 보인다.
- **옆으로 여는 문**(`axis: 'x'`·`'z'`): `doorwayWall`로 문간을 뚫고, 문짝 두께를 벽보다 얇게 해서 벽 중심선에 놓는다. 열린 문짝이 통째로 들어갈 벽 토막이 문간 옆에 있어야 한다
  (문 폭보다 긴 벽 한 토막. 문 둘 사이가 좁으면 반대쪽으로 열게 `dist`의 부호를 바꾼다). 벽 없이 열리면 문짝이 사람이 서는 자리를 쓸고 지나가므로 검사기가 막는다.
- **위아래로 여는 문**(`axis: 'y'`): 올라가는 문은 1.95 m 넘게 떠야 하고 문 위 벽이 그만큼 높아야 한다. 내려가는 문은 윗변이 바닥 위 0.1 m 아래로 내려가야 한다.
- 문간 앞뒤에는 가구나 기둥을 두지 않는다. 스폰은 문에서 `range`보다 멀리 둔다(스폰하자마자 문이 열리지 않게).
- 방 안에서 문을 닫아 둔 채 버티려면 방이 `range`보다 깊어야 한다. 복도에서 문 앞을 몰래 지나가게 하려면 복도 폭을 `range`보다 넓게 한다.
- 봇의 길 찾기는 문을 없는 것으로 친다. 봇이 다가가면 문이 열리므로 그대로 지나간다. 방장의 벽 가림 검사도 문을 빼고 본다.
- 그릴 때 위아래에 문틀 같은 어두운 띠가 둘린다.

검사기는 상자마다 `mover lift_w: y +2.8 m, 10 s cycle (hold 2 s), peak 1.4 m/s`를, 문마다 `door door_1: x +1.83 m, opens within 1.4 m in 0.22 s, …`를 출력하고, 아래를 본다.

| 검사 | 내용 |
|---|---|
| 형식 | `validateMap`: 축, 거리, 주기, 편도 이동 시간, 가장 빠른 순간의 속력, 맵 크기 안, id 겹침. 문은 주기·속력 대신 `door` 값의 범위와 다 열렸을 때 지나갈 수 있는지를 본다 |
| 길 | 지나가는 부피에 스폰(팀·개인전·폭파 진영)·발판·포털(입구와 도착)·폭파 구역·소품·도형이 없는지. 높이 0.06 m 이하의 바닥 도형(레일·차선)은 겹쳐도 된다 |
| 끼임 | 수평 상자가 멈추는 자리 앞 1.5 m 안에 도형이나 맵 가장자리가 없는지 |
| 비켜 갈 폭 | 수평 상자의 길 전체에서 적어도 한쪽에 몸이 설 자리가 이어지는지(경고) |
| 머리 공간 | 윗면의 짧은 변이 1 m 이상인 수직 상자(타는 상자)가 다 올라갔을 때 그 위 2.2 m가 비었는지 |
| 문간 | 문이 선 자리와 그 앞뒤(얇은 쪽)에 사람이 설 바닥이 있는지. 한쪽이 막혀 있으면 열려도 지나갈 수 없다 |
| 문이 들어갈 벽 | 옆으로 여는 문이 다 열렸을 때 문짝을 통째로 품는 도형이 있는지. 끼임·비켜 갈 폭 검사는 문에 하지 않는다 |
